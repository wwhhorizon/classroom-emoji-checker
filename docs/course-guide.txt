《表情符号课堂情绪检查器系统》实验指导书
课程：软件工程实践
实验类型：综合设计性实验
建议学时：60 实验学时（10 周，每周 6 学时）
团队规模：4 人/组
适用对象：本科高年级学生
一、实验背景与目的
学生情绪是了解课程内容有效性、教学反馈质量和学生学习体验的重要信息来源。学生情绪记录与学生的幸福感、学习过程和成就直接相关。教师可通过课堂情绪数据衡量教学效果，及时调整教学节奏与反馈方式，提高课堂教学质量。
本实验要求学生团队设计并实现一个“表情符号课堂情绪检查器系统”。系统支持学生在课堂中主动选择表情符号记录情绪，也支持通过 AI 推理系统对摄像头视频进行实时情绪分析并入库；教师可查看历史数据；管理员可管理用户、安排课堂用户列表、统计并导出数据。
通过本实验，学生应达到以下目标：
掌握需求分析、用例建模、领域建模和软件设计文档编写方法；
理解并实现“修改版 MVC”架构，完成客户端、后端、管理端和 AI 服务的并行开发与集成；
掌握 REST API 设计、关系型数据库设计、身份认证与基于角色的访问控制；
完成 Android 客户端或浏览器/PC 客户端开发，并实现与管理端、后端的数据交互；
集成 AI 视频情绪推理服务，理解实时数据采集、置信度过滤和数据入库流程；
完成单元测试、接口测试、端到端测试、部署与演示。
二、系统总体要求
2.1 系统角色
角色 主要权限
学生 注册、登录、修改密码、发送 emoji、查看个人历史 emoji
教师 注册、登录、修改密码、查看所授课堂/学生的 emoji 历史与统计；通过管理端查看所授课堂的实时课堂情绪看板与多维统计图表
管理员 注册、登录、查看用户数据、查看 emoji 数据、统计 emoji 数据、导出 CSV、为特定时间安排用户列表、管理实时课堂情绪看板与多维统计图表
AI 推理服务 从摄像头视频中分析情绪，生成 emoji/情绪记录并写入数据库
2.2 必做功能
客户端：
学生注册、登录、修改密码；
学生选择表情符号记录对课程内容的情绪；
学生查看个人历史 emoji；
教师登录后查看相关课堂历史 emoji 与基础统计。
后端：
用户管理、认证授权、emoji 记录存储；
课堂/课程会话管理；
为特定时间安排用户列表；
与客户端、管理端、AI 服务交互；
提供 REST API 与数据库持久化。
管理端：
管理员注册、登录；
查看用户数据；
查看 emoji 数据；
统计 emoji 数据；
导出 emoji 数据为 CSV；
安排特定时间的用户列表；
提供教师端实时课堂情绪看板，展示当前课堂实时情绪汇总与趋势；
提供按课程、班级、时间段的多维统计图表。
AI 推理集成：
从摄像头视频流中采样帧；
人脸检测与情绪分类；
将情绪结果映射为 emoji 类型，记录来源为 AI，并写入数据库；
支持置信度阈值过滤；
默认不保存原始人脸图像或视频。
2.3 选做扩展
匿名模式与聚合模式；
消息队列异步处理 AI 推理结果；
将 AI 推理能力封装为可被智能体调用的工具服务（如 MCP Server 形式）；
Docker Compose 一键部署与 CI 流水线。
三、总体架构要求
系统采用 C/S + B/S 混合架构，并实现“稍微修改过的 MVC”。
架构示意：
Android/浏览器客户端   ── REST/JSON ──┐
管理端 Web（MVC）   ── REST/JSON ──┤
AI 推理服务（Python） ── REST/消息 ──┤
▼
后端应用服务
Controller → Service → Repository
▼
关系型数据库
3.1 架构说明
客户端建议采用 MVVM 或 MVP：View 负责界面，ViewModel/Presenter 负责状态与交互，Repository 负责调用后端 API；
管理端采用 MVC：View 为页面，Controller 处理请求与路由，Model 封装业务数据与规则；
后端采用分层架构：Controller 接收请求，Service 实现业务逻辑，Repository 访问数据库；
AI 服务独立部署，通过 REST 或消息队列向后端提交分析结果；
各端通过统一 API 契约并行开发，接口变更须版本化并通知全组。
3.2 技术栈建议
模块 建议技术
Android 客户端 Kotlin + Jetpack Compose / Java + XML，Retrofit/OkHttp
浏览器/PC 客户端 React/Vue（可选）
后端 Spring Boot / Node.js Express / FastAPI
数据库 PostgreSQL / MySQL
管理端 React / Vue + MVC 路由
AI 服务 Python + OpenCV + DeepFace/FER 或轻量模型
部署 Docker Compose，Nginx，HTTPS
测试 JUnit/Pytest、Postman、Playwright/Selenium
四、数据模型要求
至少设计以下核心实体，允许合理扩展：
User：用户 ID、用户名、密码哈希、角色、邮箱、状态、创建时间；
Course：课程 ID、课程名称、教师 ID；
ClassSession：课堂会话 ID、课程 ID、开始时间、结束时间、教室/班级；
ScheduleUser：安排 ID、课堂会话 ID、用户 ID、安排时间；
EmojiRecord：记录 ID、用户 ID（AI 记录可为空或匿名）、课堂会话 ID、emoji 类型、时间戳、来源（MANUAL/AI）、置信度、设备/来源标识；
AuditLog（建议）：登录、导出、权限变更等关键操作日志。
约束要求：
密码必须加盐哈希存储，禁止明文；
角色权限在后端强制校验；
emoji 类型使用枚举约束；
AI 记录必须带置信度，低于阈值可丢弃或标记；
导出 CSV 时防止 CSV 注入；
原始视频和人脸图像默认不落库。
五、接口设计要求
后端至少提供以下 REST API 类别：
类别 示例接口
认证 POST /api/auth/register、POST /api/auth/login、PUT /api/auth/password
用户 GET /api/users/me、管理员 GET /api/admin/users
课堂 GET /api/sessions、POST /api/admin/sessions/{id}/schedule
Emoji POST /api/emoji、GET /api/emoji/history、GET /api/emoji/statistics
实时看板 GET /api/admin/dashboard/realtime?sessionId=...、WebSocket /ws/dashboard
多维统计 GET /api/admin/statistics?course=&class=&from=&to=
AI 入库 POST /api/ai/emoji-results，需服务认证
导出 GET /api/admin/emoji/export?format=csv
要求：
使用 JWT 或 Session 认证；
统一错误码与响应格式；
提供 OpenAPI/Swagger 文档；
管理员接口必须 RBAC 校验；
AI 服务接口使用独立令牌，不与学生令牌混用。
六、AI 推理集成要求
AI 服务流程：
摄像头视频 → 帧采样 → 人脸检测 → 情绪分类 → 置信度过滤 → 情绪到 emoji 映射 → 关联课堂会话 → 调用后端 API 入库
具体要求：
支持至少 5 类基本情绪/emoji 映射；
可配置采样频率与置信度阈值；
记录时间戳、来源 AI、置信度、课堂会话 ID；
默认匿名化，不存储原始人脸图像和视频；
具备断线重试和错误日志；
在实验报告说明模型局限性和误判风险。
